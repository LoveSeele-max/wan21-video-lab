# Week5 补充：VAE 3D 卷积的内存布局探针（本机，2026-11-06）

性质：CC 报告在本机 RTX 5060 Ti（sm_120，torch 2.9.1+cu128，cuDNN 91002）上的**单个卷积算子**测试。数值来自本机探索记录，不是本次发布重新执行；没有服务器 sm_89 或整段 VAE 对照。脚本：[size](../scripts/probe_conv3d_size.py)、[layout](../scripts/probe_conv3d_layout.py)。

形状取自 [VAE 峰值报告](week5_vae_peak.md) 中重建的峰值卷积：输入 `[1,96,6,482,834]`（含因果 padding），权重 `[96,96,3,3,3]`，输出 `[1,96,4,480,832]`。

脚本的“额外显存”实际为 `max_memory_allocated - memory_allocated_before - output.numel()*output.element_size()`，以 MiB 表示并四舍五入至整数。0 MiB 表示扣除基线和逻辑输出大小后的取整余量，不代表 GPU 总占用为零或严格没有 workspace。输入和权重的布局转换在进入计量函数前完成，转换时间及转换期间的峰值均未计入。

| 条件 | 额外显存 MiB | 单次耗时 ms |
|---|---:|---:|
| BF16，默认连续布局 | 7898 | 48.3 |
| FP16，默认连续布局 | 约 7890 | — |
| FP32，默认连续布局 | 885 | 52.7 |
| BF16，`cudnn.benchmark=True` | 7898 | 48.3 |
| **BF16，输入和权重转为 `channels_last_3d`** | **0** | **17.5** |
| BF16，极小输入 `[1,96,3,34,34]` | 5 | 0.1 |

本机报告的约 7898 MiB 与服务器 columns 的 requested 7897.5 MiB、allocator block 7898 MiB 量级相符。服务器分配栈已经直接观察到 native slow 卷积；本机脚本没有记录 profiler 或后端选择，内存吻合只能支持同类展开缓冲区的假设，不能单凭此表证明本机 cuDNN/native 的实际 dispatch。小尺寸 5 MiB 也不证明小尺寸使用了 cuDNN。

每种条件仅一次预热、一次测量，输入随机且未固定种子；没有逐次原始结果、完整环境转储或数值误差检查。48.3/17.5 约为 2.76，只描述预转换布局的这次单算子结果，不是整段 VAE 加速比。

尚未查明的部分：
- 本机和服务器的实际 dispatch 及对应版本、布局、dtype 条件；原探针没有记录后端，不能将尺寸认定为已确认原因；
- 服务器 sm_89 是否同样如此。服务器 trace 已出现 `slow_conv_dilated`，方向一致，但仍需在服务器上跑同一脚本；
- 转换布局本身的拷贝开销、整段 VAE 解码的峰值和耗时变化，以及输出的数值误差。

对第 6–7 周的意义：布局与后端调查值得先于空间分块验证；若实施，应提供可回退开关。7897.5 MiB 约为 7.71 GiB，只是既有临时申请的大小，不能直接当作可实现的整段峰值降幅。转换可能引入新副本，峰值也可能移动；是否转到文本阶段必须经过完整生成测量。未来按[性能规则 v2](performance_rules_v2.md)单独预登记，并核对固定 latent 原始输出误差。本周未实施该候选改动。
