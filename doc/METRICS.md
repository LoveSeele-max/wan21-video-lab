## 一、三套口径，分开测

主线三件事必须**分别测量、分别报告**，禁止交叉推导。

| 口径 | 怎么测 | 陷阱 |
|---|---|---|
| **延迟** | 同一进程内计时；明确是否含加载与首次运行（compile/warmup）；报均值与范围，不只报最快一次 | 首次运行含编译/权重加载，不能与稳态混为一谈 |
| **峰值显存** | `torch.cuda.max_memory_allocated` 与 `nvidia-smi` 分别记录，注明口径 | 分配器峰值 ≠ 卡上占用；两个数字都要留 |
| **质量** | 见第三节。自动指标 + 人工判据**分别报**，不合成总分 | 自动指标容易把"不动"判成"一致性好" |

### 1.1 操作定义（写进 `scripts/bench.py` 的注释）

**三种耗时，分开定义、分开报**：

| 名称 | 起点 → 终点 | 用途 |
|---|---|---|
| 冷启动 | 进程启动 → 视频写盘（含权重加载、首次编译） | 用户首次体验；`--compile` 的首次开销 |
| 稳态端到端 | 预热后一次 generate 开始 → latent/视频保存完成（含该路径每次重新加载模型） | 主比较口径；2026-10-15 与 Week 2 实施统一 |
| 阶段耗时 | 文本编码 / 去噪循环（总计 + 单步均值）/ VAE 解码 / 保存 | 回答"为什么"，定位瓶颈 |

**计时规则**：

- GPU 是异步执行的，**每个计时边界前先调用 `torch.cuda.synchronize()`**，或者用 `torch.cuda.Event(enable_timing=True)`。否则测到的只是任务提交的时间。
- 墙钟时间用 `time.perf_counter()`，不要用 `time.time()`。

**峰值显存规则**：

- 预热**之后**、正式计时**之前**，调用一次 `torch.cuda.reset_peak_memory_stats()`。否则预热时的峰值会混进结果。
- **分阶段峰值**：每个阶段开始前 reset，结束后读 `max_memory_allocated()` 和 `max_memory_reserved()`。这样读到的是该阶段内的**绝对占用峰值**（包含阶段入口时已经驻留的张量），不是增量。如果需要增量，就另记"峰值 − 阶段入口时的 `memory_allocated()`"，并标明口径。
- **总峰值**：reset 会清掉之前的峰值，所以最后一次读数**不代表**整次生成的峰值。总峰值取各阶段峰值的最大值，前提是各阶段**首尾相接、覆盖整次生成**；或者另跑一次不分阶段 reset 的测量，直接读总峰值。两种做法选一种，写进脚本注释。
- **插桩开销**：分阶段同步和 profiler 只用于**定位**。最终的性能对照中，基线与优化配置要用**同一套**插桩方式（都开或都关），避免把插桩开销的差异算成优化收益。
- `nvidia-smi` 外部采样要**注明采样间隔**（如 `--loop-ms=100`）。采样间隔大于峰值持续时间时，峰值会被漏掉。

**两种重复，不能混为一谈**：

| 重复 | 估计的是 | 默认次数 |
|---|---|---|
| 同一提示词 + 同一种子，连续计时 N 次 | **测量噪声**（计时稳定性） | 3 |
| 同一提示词，换生成种子 | **出片随机性**（质量波动） | 3 |

延迟结论用第一种。质量结论用第二种，再跨提示词汇总。

**温机条件**：每次正式测量前跑固定次数的预热（默认 1 次完整生成）。换配置后重建进程，避免残留状态影响。

**单次数字不作为结论**：报均值与范围。

**禁止**：不以显存下降推导速度提升（量化与卸载都可能变慢）；不把单次最快结果当代表值。

## 二、公平比较

1. 对照前**冻结**提示词清单、生成种子、帧数及其他生成设置，登记全部预定配对。
2. 基线（未优化）与优化配置使用**同一提示词、同一种子、一致设置**逐条配对。
3. **一次只改一个变量**。测 attention 后端时，精度、卸载、步数、编译全部固定。
4. 明确失败、无法判断与运行失败**不静默删除**；保留该预定尝试及原因。
5. 配对减少随机性干扰，**不消除随机性**，也不代替事先确定的结论规则。

**配置命名**：所有实验配置写入单独文件（如 `configs/*.yaml` 或 `*.sh`），文件名即配置名，结果表直接引用。不靠记忆复述参数。

## 三、质量评价：极简版

### 3.1 人工判据（主）

固定几档，**评分者不知道样本属于哪个配置**（基线/优化混合、顺序随机）：

| 维度 | 档位示例 |
|---|---|
| 画质与结构 | 稳定 / 轻微退化 / 明显崩坏 |
| 时序与运动自然度 | 连贯合理 / 局部缺陷 / 严重异常；静止不自动判时序失败，动作要求另看符合度 |
| 提示词符合度 | 符合 / 部分符合 / 不符合 |
| **与基线相比** | 盲评逐维度选 A 更好 / 无明确优劣 / B 更好，并记录程度；解盲后换算为相对基线结果 |

最后一栏是关键：优化的目的是"不变差地变快"，所以判据主体是**相对基线的退化程度**，不是绝对好坏。

保留"无法判断"，不合成单一总分。

2026-10-18 冻结的操作标准 v1.0 见 [week3_rubric.md](../notes/week3_rubric.md)：单条视频三项各用 2/1/0 档位；配对比较另记方向、程度和时间证据。两条已知身份的校准样例保留用户原评分及局限，不进入正式质量汇总；标准冻结不等同于正式评价完成。

### 3.2 自动指标（辅）

只保留两个便宜指标，用于初筛、定位退化：

- **帧间一致性**：相邻帧之间的 SSIM（无网络依赖，首选）。也可加报 LPIPS，但它依赖预训练网络与权重，需要额外的依赖和许可核对。
- **文本对齐**：帧与提示词的 CLIP 相似度，报**均值与最低值**。最低值补充记录低相似度采样帧，但不保证定位局部崩坏；Week3 探针已显示全局范围规则的局限。

**不得单独使用**：帧间一致性会偏爱静止视频；当前帧级 CLIP 相似度不能单独作为动作符合度证据，不据此泛化为所有动作都无法区分。自动指标**只作异常线索**，质量结论仍需人工判据及其执行证据支持。

### 3.3 反例探针（必做，正式对照前）

用四个样本确认指标"能区分什么、不能区分什么"：

| 样本 | 检验 |
|---|---|
| 正常运动 | 好样本上的正常取值 |
| 首帧重复形成的静止视频 | 指标会不会**偏爱不动的视频** |
| 闪烁、模糊、局部变形 | 对**局部/瞬时退化**是否敏感 |
| 画面清楚但动作与提示词不符 | 能否区分**画质**与**文本符合度** |

逐指标记"能区分 / 不能区分 / 部分区分"。**不能用某指标下超出其能力的结论。**

## 四、报告模板（主线）

一次优化测量的报告单元：

| 字段 | 内容 |
|---|---|
| 配置名 | 指向配置文件 |
| 相对基线改了什么 | 一句话，一个变量 |
| 延迟 | 稳态端到端：均值 ± 范围（3 次） |
| 阶段耗时 | 变化集中在哪个阶段（支撑"机理"一栏） |
| 峰值显存 | allocator / nvidia-smi 两个数 |
| 质量 | 人工抽检 N 例的档位分布 |
| 机理 | 为什么快/慢，代码位置 |
| **失效条件** | 什么情况下这项不适用 |
| 结论 | 可用 / 有条件可用 / 不推荐 |

**覆盖率短表（每个配置必附）**：防止 OOM、生成失败或无法评分的样本从汇总里悄悄消失。

| 配置 | 预定生成数 | 成功生成 | OOM / 运行失败 | 可评分 | 无法判断 |
|---|---|---|---|---|---|

"可评分 / 无法判断"按**每个质量维度**分别记录，一条视频可能画质可评、动作无法判断。做配对比较时，只比较双方在该维度上都可评分的配对，并报出这样的配对有多少。

质量档位的占比**以"预定生成数"为分母**另报一遍，与"以可评分数为分母"的占比并列。两者差距大，说明配置本身不稳定，这一点本身就是结论。

**汇总表**：每行一个配置，列为延迟、峰值显存、质量档位、是否可叠加。**不做加权总分**——不同场景下权重不同，给表不给分。

**叠加配置单独列表**：注明与哪些单项冲突（见 EXPERIMENT_PLAN.md 第七节）。

## 五、次要线（时间步与 LoRA 配置）的报告纪律

- 初筛单训练种子，**结论只作探索性**，不写"稳定优越"。
- 生成种子与训练种子**分开记录**；改生成种子不能说明 LoRA 是否稳定。
- 未检出差异 → 写"在当前任务、配置、样本量与口径下未检出"，不声称该因素无关紧要。
- **不得把"训练后画面更像训练集"等同于"动作能力提升"**——可能只是外观过拟合，甚至伴随运动退化。

## 六、暂缓清单（仅在出现正效应后考虑）

以下项目**现阶段不做**。它们是论文级评价成本，用来支持一个 30 秒扫过的简历条目不划算：

- 对留出真实视频做 MMD 等分布距离
- 光流 warp 误差（需引入 RAFT 类模型 + 许可审查）
- ImageReward 等奖励模型
- 多训练种子复核
- 盲评的评分者间一致性统计

**触发条件**：次要线出现明确正效应，且准备写正式实验报告时，再逐项评估是否值得引入。

## 七、人工检查

- **评什么**：画质与结构、时序质量、提示词符合度、相对基线退化程度（见 3.1）。
- **刻度**：每维度三档，判据文字写在上表。
- **抽检量**：每配置 N 例，N 在探针阶段确定（建议 10 起）。
- **2026-10-22 评分量冻结**：每配置预定 36 对三项配对比较，固定 12 段子集做三项绝对评分，见 `configs/scoring_frozen.yaml` 与 `notes/week4_prereg.md`。人工耗时已由用户取消，不作为完成条件；性能计时照常保留。
- **盲评**：配置混排、顺序随机。
- **不能事后补写**：判据与抽检量在正式对照前定好；事后新增的指标标为探索性，不追认成功。

## 八、结论边界

- 所有结论限定在**当前任务、配置、样本量与评测口径**内。
- 报告同时给出收益、代价与失效条件，不只报收益。
- 人工检查与自动指标**分别报告**，不以单一数字概括全部效果。
- null 结果照实写，不包装成提升。
