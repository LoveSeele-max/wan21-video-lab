  - 修正 A0.3、A1.1、A1.5、A4.1；
  - 新增 A0.8、A1.11、A1.12；
  - 参数类条目的核对来源由"文档"改为"源码"。

**核对来源约定**：参数与行为类断言，**以源码为准**。`docs/wan.md` 与代码存在不一致，见 A0.8。凡是写"已核实"的条目，都要注明核对的是源码还是执行结果，以及对应的 commit/日期。当前标注的核对时间点：main 分支，2026-10-11。阶段 0 固定 commit 后要再复核一遍。

**用途**：所有"还没被验证、但结论依赖它"的说法登记在此。跑实验时逐条打勾或推翻。

> **被推翻的条目不是失败，是实验结果的一部分，要写进报告。**

**使用纪律**

1. 每条必须有"验证方式"和"判定标准"，否则它是愿望不是假设。
2. 状态：`已核实`（有源码/文档/执行结果支撑）、`有证据但需适配`、`未验证`、`不成立`。
3. 不把已核实的硬事实降级成假设，也不把假设升格成事实。
4. 冻结后改动须登记原因与影响范围；事后新增的指标标为探索性，不追认预设成功。
5. 状态变更写明日期与依据（源码位置 / 命令输出 / 报告章节）。

**项目范围**：Wan2.1 T2V 1.3B + Musubi Tuner、480P、单卡 LoRA 优先；主线为推理与训练性能优化，次要线为时间步采样与动作/外观适配。

## 二、推理优化（主线）

| ID | 假设 | 状态 | 验证方式 | 判定标准 |
|---|---|---|---|---|
| A1.1 | 不同 attention 后端（`torch`/`xformers`/`sageattn`/`flash`）在延迟上有可测差异 | 未验证。**前提已核实（源码）**：`sdpa` 是 `torch` 的别名，`flash` 与 `flash2` 走同一分支，不重复测；`flash3` 仅支持 Hopper，本机硬件不适用 | `--attn_mode` 逐项扫描，其他全固定 | 得到非退化差异；若无可测差异，结论为"该任务下不敏感"，同样写进报告 |
| A1.2 | 各 attention 后端依赖可成功安装 | 未验证 | 分别安装并跑通一次 | 安装失败也记录，不静默跳过 |
| A1.3 | `--fp8` / `--fp8_scaled` 能显著降显存，且质量代价可接受 | 未验证 | 对比无量化 / fp8 / fp8_fast 的显存、延迟与人工判据 | 收益与质量代价**一起报** |
| A1.4 | `--fp8_fast` 会降低输出质量（上游文档提示） | 有证据但需适配。**注意（源码）**：只在 `--fp8_scaled` 分支内生效，代码不做校验，单独开启不报错但也无效果 | 与 `--fp8_scaled` 一起开，人工盲评对比 | 确认或推翻；推翻也是结果 |
| A1.5 | `--blocks_to_swap` 档位与显存/延迟存在可测的权衡关系 | 性能权衡未验证。**2026-10-14 固定 checkout 副本静态核对**：1.3B 为 30 层，`WanModel.enable_block_swap` 检查 `<= num_blocks - 1`，上限 29；旧“代码不校验”结论错误。见 `../notes/param_check.md` 第 7 项 | 扫描若干档位；源码副本版本一致性仍待 Git 校验 | 得到显存—延迟曲线 |
| A1.6 | `--infer_steps` 存在可观测的质量—延时权衡 | 未验证 | 固定模型与样本，扫若干步数 | 得到非退化曲线；全区间无差异则记"不敏感" |
| A1.7 | `--compile` 带来可测加速 | 未验证 | 固定 shape 下开关对比，预热后计时 | 报稳态加速比与首次编译开销 |
| A1.8 | `--cfg_skip_mode` + `--cfg_apply_ratio` 能降延时且质量退化可控 | 未验证 | 逐模式对比 | 报延时收益与质量档位 |
| A1.9 | 各优化项之间存在冲突，不能简单叠加 | 未验证 | 单项测完后测组合 | 给出可叠加组合与冲突组合清单 |
| A1.10 | 延迟与峰值显存可同口径测量且可复现 | 未验证 | 按 METRICS 1.1 的操作定义：同步计时、预热后重置峰值 | 三项来自同一次运行记录；同配置 3 次范围可接受 |
| A1.11 | 1.3B 480P 能在 RTX 5060 Ti 16G 上完成推理 | 未验证 | 本机实测：**先确定能跑通的 attention 后端并固定**，再依次加 fp8 + fp8_t5、`--blocks_to_swap`、`--vae_cache_cpu` | 只跑通一个配置时写"找到可运行配置"；比较过多个配置才写"已测配置中代价最小"。跑不通就记录卡在哪个阶段、峰值多少。服务器结果只用于筛选，不直接外推到本机 |
| A1.12 | 存在一个明显的单一瓶颈（某阶段占稳态耗时或峰值显存的大头） | 未验证——**不预设是哪一个** | 阶段计时 + `torch.profiler` | 有就针对它优化；耗时分布平均，则结论为"无单一瓶颈"，并按收益/成本排序候选项 |

## 冻结与修订规则

- 预检前确定预检配置；正式对照前确定任务、数据划分、指标、样本规模与结论规则。
